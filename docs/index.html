Version control for Claude Code

Your AI agent's memory, kept as history.

Claude Code writes what it learns about you and your projects into files, next to your instructions and skills. None of it has history. memsaga commits every change to a git repository you own, names each commit after the conversation that made it, and brings back the edits you make anywhere else.

Who it is for

Anyone whose Claude Code knows things worth keeping

Claude Code is used for more than code. If it keeps notes for you, the notes deserve a history.

You write code across many projects
"Why is this rule in CLAUDE.md, and who added it?"

git blame names the commit, and the commit names the conversation. Undo a bad edit with memsaga restore, after reading the diff.

You write, research or plan with Claude
"It rewrote my style guide. What did it say on Monday?"

Your instructions, the facts Claude saved about your work, and any file you point memsaga at, such as ~/notes/plan.md, are kept like drafts of a manuscript. Every earlier draft is still there.

You work on two machines, or two accounts
"I taught it this on my laptop. Does my desktop know?"

Memory, skills and hooks reach the other machine the next time you use Claude there. A work account and a personal account each keep their own folder in one repository.

You let Claude tidy its own memory
"Merge the duplicates, drop what is stale. I will review."

The clean-up lands as ordinary commits under one conversation. Keep what helps, and roll back the rest with memsaga restore --all.

How it runs

On its own, after every reply

There is nothing to remember to run. The work happens in the background and takes well under a second.

  1. Claude changes a file

    A memory, CLAUDE.md, a skill, or a file you listed.

  2. The reply ends

    Everything that changed becomes one commit, named after the conversation.

  3. It is pushed

    To your private GitHub repository, at most every ten minutes and when the session ends.

  4. Your other machine has it

    The next time you start a session or send a prompt there.

Two-way sync

Fix a memory from your phone

The repository syncs both ways. An edit made on GitHub, on another machine or in the local copy reaches the file Claude reads. A conversation that already read the old text is told what changed.

Ask in your own words

The companion-docs skill starts when you ask for a version of a document in another language (中文版, 日本語版, en français) or for a note about a repository. Claude writes it at the path that mirrors the source.

Found again by its path

Before Claude summarises or translates a document, it checks whether a companion exists, so the next conversation builds on the last one instead of starting over.

Drafts before the source

Write a design in your own language first. It waits at the path the real document will have, marked as a draft.

One list of them all

The companions skill adds /companions to Claude Code; memsaga companions prints the same list in a terminal: status, path and source.

Both skills come with memsaga install --skills. Companions are committed, pushed and synced like everything else, so you can read them on GitHub from anywhere. These three, in the example repository

Built to be trusted

It keeps history. It does not take over.

Your files stay where they are

The repository holds copies. memsaga writes Claude's files only when you restore one, or when an edit you made elsewhere arrives.

Every version can come back

Restore one file, or all of them, from any point in history. A restore shows the diff and waits for your yes.

It stays out of Claude's way

If something fails, Claude Code carries on as usual, and memsaga status tells you what happened.

What you add stays

Files you put in the repository yourself are committed and never removed by memsaga.

Secrets stay out

Not copied: ~/.claude.json, credentials, transcripts and caches. settings.json only if you ask.

You own the repository

Plain git, on your disk and in your own private GitHub repository. No service to sign up for, no telemetry.

Install

Set it up once

  1. The installer puts a prebuilt memsaga in ~/.cargo/bin, for Macs (Apple silicon and Intel) and Linux (x86_64 and arm64). You need git. To build from source instead: cargo install --git https://github.com/grimmerk/memsaga memsaga --locked.
  2. init creates the data repository and replays the edits your recent conversations recorded, so the history starts weeks back. It goes in memories inside the folder where you keep code (~/git, ~/code, ~/src, ~/Projects or ~/dev), or in ~/memories; --repo picks another place, and --dry-run shows the choice first.
  3. install connects memsaga to Claude Code. With --skills, Claude can also answer questions about the history.
  4. gh repo create is optional. With a private GitHub repository, pushes and two-way sync happen on their own.

Keep the data repository private. Memory holds whatever Claude learned while working with you, which often includes details of your work.

terminal
$ curl --proto '=https' --tlsv1.2 -LsSf \
    https://github.com/grimmerk/memsaga/releases/latest/download/memsaga-installer.sh | sh
$ memsaga init --dry-run   # what would be imported
$ memsaga init
$ memsaga install --skills
$ gh repo create memories --private --push \
    --source "$(memsaga repo)"   # optional: a private remote
$ memsaga status
# to try it on example data first, run these after the install line;
# your real Claude Code config is never read or written
$ git clone https://github.com/grimmerk/memsaga
$ memsaga/demo/setup.sh && source /tmp/memsaga-demo/env.sh
Out of scope

What memsaga leaves alone, and what to use instead

WhatWhy it is left outInstead
Conversation transcriptsLarge, and mostly your work rather than configurationRaise cleanupPeriodDays in settings.json to keep them longer
Marketplace pluginsPackages you can install again, not files you wroteInstall them again; a mirrored settings.json lists which
Credentials and login stateSecrets must never enter a repositoryYour system keychain or a password manager
Fast-changing settings (model, effortLevel)Rewritten on every /model and /effortNothing: each machine keeps its own

Status: early, in daily use by its author on macOS, tested in CI on Linux. Claude Code is the only agent today; others are on the roadmap.

mem, for memory. saga, for history.

Saga is Old Norse for "story" or "history", the word for the medieval Icelandic narratives that followed people and events across generations. A repository of memory that keeps every version is the story of how that memory came to be, one change at a time.
